# 수호인 학습용 사이트 요구사항 (초안 v0.2)

대상: https://suhoin.kr/ 의 화면에서 관찰할 수 있는 기능을 학습용으로 재구현한다.
용도: REA 기반 구현(`suhoin-lab/`)과 비교하기 위한 독립 구현(`suhoin-lab-b/`)의 입력 문서.

## 0. 작성 원칙

- 이 문서는 사이트 화면과 사용자 눈에 보이는 동작만 근거로 한다.
- 스크립트 내부 로직, 단가표, 필드 이름, 검증 규칙 등 소스 분석으로만 알 수 있는 값은 쓰지 않는다.
- 화면만으로 알 수 없는 항목은 `[확인]`으로 표시한다. 구현자는 URL을 직접 참조해 채우거나, 모르면 가정을 명시한다.
- 폼 검증 규칙처럼 원본이 정해 둔 값은 요구하지 않는다. 구현자가 합리적으로 설계한다.

## 1. 범위

### 포함
- 3장의 페이지 전부.
- 계산기, 문의 폼, 입사지원 폼, 메인 슬라이드, 팝업, 반응형 메뉴.
- 폼 접수는 이 서버의 로컬 저장소에만 저장한다.

### 제외
- 사진과 업로드 이미지, 배너, 협력사 로고, 인물 사진. 같은 크기의 플레이스홀더로 대체한다.
- 외부 연동: reCAPTCHA, 지도, 우편번호 검색, SNS 링크, 추적 스크립트.
- 실제 기업으로의 제출, 메일 발송, 파일 첨부.
- 관리자 화면.
- 사업자 정보와 연락처는 더미 값으로 대체한다.
- 로고는 텍스트로 대체한다.

## 2. 공통 요구사항

### 2.1 레이아웃
- 상단 헤더: 로고, 대메뉴 5개, 햄버거 버튼.
- 대메뉴: 회사소개, 사업소개, 장애예술인 일자리 지원, 견적문의, 입사지원.
- 햄버거 버튼: 전체 메뉴를 펼친다. 좁은 화면에서는 측면 메뉴로 열린다. [확인] 전환 폭.
- 서브 페이지 상단: 큰 제목, 부제 문구, 장식 이미지 영역, 소메뉴(LNB). 현재 페이지는 강조 표시한다.
- 현재 위치 표시(홈 > 대메뉴 > 소메뉴). [확인] 각 단계 클릭 시 동작.
- 우측 고정 빠른 링크 아이콘 3개. 외부로 나가지 않는다.
- 푸터: 문의 전화와 영업시간, 하단 링크(회사소개, 개인정보처리방침, 이메일무단수집거부, 이용약관, 오시는 길), 회사 정보(더미), "맨 위로" 버튼.

### 2.2 반응형
- 데스크톱, 태블릿, 모바일 3단계. [확인] 구체 폭 기준.
- 모바일에서 메뉴 접근과 폼 입력이 가능해야 한다.

### 2.3 접근성과 품질
- 모든 이미지에 `alt`를 둔다.
- 키보드로 폼 입력과 제출이 가능하다.
- 깨진 이미지와 404 리소스가 없어야 한다.

- 위 목록 밖의 페이지가 화면 메뉴에서 더 발견되면 `NOTES.md`에 기록한다.

## 4. 고용부담금 계산기 (`/support/account`, 메인 일부)

### 입력
1. 사업체 구분 선택(택1, 기본값은 첫 항목): 민간사업주, 공공기관/지방공기업, 국가/자치단체(공무원 아닌 근로자).
2. 전체 근로자 수(상시근로자 수): 숫자 입력. 빠른 더하기 버튼 +1000, +100, +10, +1과 초기화 버튼.
3. 현재 고용 중인 장애인 근로자 수 3종: 경증 장애인, 중증 장애인(월 60시간 이상), 중증 장애인(월 60시간 미만). 각각 −/＋ 버튼과 직접 입력.
4. 버튼: 부담금 조회, 재입력(전체 초기화).

### 출력
- 의무 고용인원(명), 미달 고용인원(명), 월 부담금(원), 연도별 연간 부담금(원), 총 예상 금액. [확인] 표시 연도 범위와 배치.

### 규칙
- 계산 규칙은 사이트의 제도 안내 페이지(`/support/system`)와, 같은 입력으로 실제 조회한 결과를 근거로 파악한다.
- 구분별 의무고용률, 인원 환산 방식, 부담금 단가와 구간은 모두 `[확인]`이다. 근거를 `NOTES.md`에 적는다.
- 입력이 비정상일 때(빈 값, 기준 미만 등)의 동작과 안내 문구도 `[확인]`이다.

### 비교용 필수 케이스
구현자는 사이트에 같은 입력을 넣어 결과를 기록하고, 아래 케이스로 자체 테스트를 만든다.
- 민간사업주, 근로자 100명, 장애인 0명.
- 민간사업주, 근로자 1000명, 경증 10명, 중증(60시간 이상) 5명.
- 공공기관, 근로자 500명, 장애인 0명.
- 경계: 49명, 50명.

## 5. 메인 페이지 (`/`)

1. 상단 롤링 배너. 자동 전환. 이미지는 플레이스홀더.
2. 소개 문구와 회사소개 링크.
3. ABOUT US 블록: 설명 글과 이미지.
4. 장애예술인 창작활동 갤러리: 자동 슬라이드, 좌우 화살표. 이미지는 플레이스홀더.
5. 서비스 안내 아이콘 목록과 견적문의, 입사지원 바로가기 박스.
6. 계산기(4장과 동일 동작).
7. 협력사 영역: 흐르는 슬라이드. 로고는 플레이스홀더.
8. 팝업: 진입 시 표시. "닫기"와 "오늘 하루 보지 않기"가 있다. 내용은 학습용 안내 문구로 대체한다.
- [확인] 5번 이후 섹션의 정확한 구성과 순서, 팝업 재노출 기준.

## 6. 견적문의 폼 (`/customer/inquiry`)

- 입력 항목: 페이지에 보이는 항목을 따른다. [확인] 항목 목록, 순서, 필수 표시.
- 필수 항목 검증, 형식 검증, 오류 안내 방식은 구현자가 설계한다.
- 개인정보 수집 동의 체크가 있어야 제출된다.
- 성공하면 접수 안내를 보여주고 폼을 비운다.
- 접수 내용은 서버 로컬 파일에 저장한다.
- 우편번호 검색 버튼은 외부 연동이라 동작하지 않고 안내 문구만 보여준다.

## 7. 입사지원 폼 (`/employment/write`)

- 입력 항목: 페이지에 보이는 항목을 따른다. 날짜 선택 입력이 있다. [확인] 전체 항목, 순서, 필수 표시.
- 검증과 저장 방식은 6장과 같은 방식으로 설계한다.

## 8. 비기능 요구사항

- 의존성: 서버는 Node 내장 모듈만 쓴다. 프런트는 자유롭게 고르되 번들 크기를 보고한다.
- 실행: 명령 한두 개로 실행된다. README에 명령을 적는다.
- 저장: 접수 데이터는 `data/` 아래 파일. 저장소에 올리지 않는다.
- 보안: 서버 측에서도 입력을 검증한다. 요청 본문 크기를 제한한다. 정적 파일 경로 탈출을 막는다.
- 개인정보: 학습용 더미 값만 입력하도록 폼 상단에 안내한다.

## 9. 수용 기준 (비교 테스트에 그대로 쓴다)

1. 3장의 19개 경로가 모두 200이고, 없는 경로는 404다.
2. 모든 페이지에서 깨진 이미지가 0개다.
3. 모든 서브 페이지에서 LNB 현재 항목이 맞게 강조된다.
4. 4장의 필수 케이스에서 결과가 원본 사이트와 일치한다.
5. 문의와 입사지원 폼은 빈 값으로 제출하면 거부되고, 정상 값은 저장된다.
6. 메인 슬라이드가 동작하고 팝업의 "오늘 하루 보지 않기"가 유지된다.
7. 좁은 폭과 넓은 폭에서 메뉴가 열리고 닫힌다.

## 10. 구현자에게

- 원본 URL을 직접 참조해 `[확인]` 항목을 채운다. 채운 근거(어느 페이지의 어떤 화면)를 `NOTES.md`에 남긴다.
- 확인하지 못해 가정한 내용도 `NOTES.md`에 적는다.
- 이 문서에 없는 기능은 만들지 않는다.
